Origin Passport Support Runbook

Verification, replacement, import triage, and escalation
Runbook: OPS-OP-012  ·  Version: 1.3  ·  Updated: 2026-05-18  ·  Audience: Wholesale Operations and Support

1. Use this runbook when

  • an operations specialist is preparing an Origin Passport for shipment;
  • a retailer reports that an Origin Passport cannot be imported;
  • a recipient says passport content does not match the shipment; or
  • an issued passport must be replaced after an approved correction.
Stop and escalate immediately if a file contains supplier pricing, producer personal contact information, internal quality notes, employee comments, credentials, or other information outside the approved wholesale schema. Do not resend the file.

2. Pre-delivery verification

  1. Open the finished batch and confirm the product name and batch number against the shipment record.
  2. Confirm that origin, producer or cooperative, harvest year, cacao percentage, certification status, production date, and shipment date have been approved.
  3. Generate the passport through the approved workflow for the shipment.
  4. Record the Origin Passport ID in the shipment handoff.
  5. Check the recipient's current integration instructions for the required file type, column names, date representation, and transfer channel.
  6. Inspect the generated file before transfer. Confirm that prohibited fields are absent.

Do not infer a recipient's required format from an earlier shipment or from the fact that a file opens locally. Use the current partner requirements supplied with the pilot or account handoff.

3. Import failure triage

CheckWhat to verifyAction

Media typeDownload or transfer metadata identifies the expected content type.Capture the observed value for Engineering.
HeadersHeader names, spelling, order, and count match the partner contract.Record differences; do not manually redesign the shared schema.

DatesDate values follow the required representation and are real calendar dates.Correct governed source data if wrong; do not conceal a source error with an ad hoc file edit.
EncodingThe file uses the required character encoding and producer names render correctly.Capture parser errors and the affected field.

4. Information to collect

Before escalating an import failure, collect:

  • retailer, shipment, product, and batch identifiers;
  • Origin Passport ID and generation time;
  • requested file type and schema reference;
  • downloaded filename and observed media type;
  • the retailer's exact error message and failure time;
  • whether the file opens in a format-aware parser; and
  • the header row and field count, excluding any prohibited information.
Preserve evidence: Keep the originally issued artifact in the restricted support case. Do not overwrite it with a locally edited copy.

5. Replacing an incorrect passport

  1. Confirm the correction has been approved in the governed source record.
  2. Generate a new Origin Passport; do not edit the issued snapshot in place.
  3. Verify the replacement using the pre-delivery checklist.
  4. Record which passport the new issuance supersedes.
  5. Send the replacement through the approved channel and clearly identify it as the current version.
  6. Retain the original according to policy and close the support case with both identifiers.

7. Do not

  • rename one file type to another and assume the content was converted;
  • manually add prohibited or unapproved fields;
  • overwrite a previously issued immutable passport;
  • send screenshots as substitutes for machine-readable files; or
  • promise support for a format or schema before Engineering confirms it.
